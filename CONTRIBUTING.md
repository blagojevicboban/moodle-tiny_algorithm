# Contributing to tiny_algorithm

Thank you for helping. This plugin is part of the Algorithm family:
[tiny_algorithm](https://github.com/blagojevicboban/moodle-tiny_algorithm) (flowchart editor, interpreter, code
generation), [filter_algorithm](https://github.com/blagojevicboban/moodle-filter_algorithm) (runnable flowcharts in
pages) and [qtype_algorithm](https://github.com/blagojevicboban/moodle-qtype_algorithm) (graded flowchart questions).
If you work with Claude Code, the skill in `.claude/skills/algorithm-contributing/` has the same rules in more detail.

## Workflow

1. Take an open issue (or open one first) and say in it that you are working on it.
2. Create a branch from `main`: `fix/<short-name>` or `feature/<short-name>`. Never push to `main` directly.
3. One topic per pull request; describe what changes for teachers or students and how you tested it.
4. Merge when CI is green. Release tags `v*`, versions and the Marketplace are the maintainer's.
5. **Do not change `version.php`, `CHANGELOG.md` or `description.html`**; say in the pull request when your change
   needs an upgrade step, a capability, a cache or a web service.

## Rules

- Every PHP, JavaScript and Mustache file starts with the GPL boilerplate header, as the existing files do.
- No hard-coded user-facing text. Widget texts: `STR.en` in `amd/src/strings.js` (tiny_algorithm) plus `ui_<key>` in
  `lang/en`, `lang/sr_lt` and `lang/sr_cr` (ekavian Serbian). The other 12 languages are generated by the maintainer.
- No larger HTML built in JavaScript (templates, or `createElement` with `textContent`).
- A change of the flowchart language goes into both interpreters (JavaScript in tiny_algorithm, PHP in
  qtype_algorithm) and passes the parity check (`tests/fixtures/make_parity.mjs` and `check_parity.php` in
  qtype_algorithm).
- Privacy API, backup and restore, capability checks as the reviewers of the Moodle Plugins directory expect.
- No emoji in code, texts or examples.

## Checks (the same as CI)

```sh
moodle-plugin-ci phplint
moodle-plugin-ci phpcs --max-warnings 0
moodle-plugin-ci phpdoc --max-warnings 0
moodle-plugin-ci validate
moodle-plugin-ci mustache
moodle-plugin-ci grunt --max-lint-warnings 0
moodle-plugin-ci phpunit --fail-on-warning
```

Node tests: `node --import ./tests/register.mjs --test "tests/*.test.mjs"` (TypeScript tests need `tsc`).

Commit `amd/build` together with `amd/src` (`npx grunt amd` in the Moodle root).

## Security

Do not open public issues for security problems: write to the maintainer through the contact on the GitHub profile.
